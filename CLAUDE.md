# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

This is a full-stack web application for visualizing and validating animal tracking data from FlyHostel experiments (fly behavior research at Liu Lab @ VIB-KU Leuven). It displays identity assignments produced by YOLOv7+idtrackerai, allowing researchers to review and correct them frame-by-frame.

- **Backend**: Python Flask API (`idtrackerai_validator_server/`)
- **Frontend**: React 18 app built with Vite (`idtrackerai-validator-client/`, git submodule)

## Running the Server

**Backend (default port 5000):**
```bash
VALIDATOR_EXPERIMENT=FlyHostel4/6X/2023-08-31_13-00-00 ./start_server.sh
# or on port 5001:
VALIDATOR_EXPERIMENT=FlyHostel4/6X/2023-08-31_13-00-00 ./start_server_5001.sh
```

Or directly:
```bash
VALIDATOR_EXPERIMENT=FlyHostel4/6X/2023-08-31_13-00-00 BACKEND_PORT=5000 \
  python idtrackerai_validator_server/app.py
```

**Frontend:**
```bash
cd idtrackerai-validator-client
npm start   # Vite dev server on port 3000, /api proxied to $REACT_APP_BACKEND_PORT (5000)
npm run build   # -> build/ (static/js/main.<hash>.js, as the server and CI expect)
```

## Architecture

### Backend (`idtrackerai_validator_server/`)

- **`app.py`**: Flask application — all routes and request handling. The `VALIDATOR_EXPERIMENT` env var selects the experiment at startup. Uses a global thread `Lock` for concurrent frame access. `/api/animal_metadata`: per identity `sex`, `genotype`, `gbx` (the `GBX` column, `"0"` when missing or empty), `light_cycle` (`merge_light_cycle`, so also the older encodings in `condition` / `experiment` / `vial`), `age` (`age_min`), from `ethoscope_metadata` or, without database, the sheet rows (`_extra_metadata`). `_open_experiment` (startup and `/api/load`) also opens experiments without database (not analyzed yet): `db_manager` stays `None`, the SQLAlchemy URI is `:memory:` (sqlite would create an empty `.db`, which the index would then list), and `STORE_INFO` holds the store's frame range, `index.db` (frame times) and the metadata sheet rows (`overview.sheet_flies`: `reference_hour` for ZT, sex/genotype for `/api/animal_metadata`). Frame, contours (`<date>.conf`), frame range, framerate and `/api/tracking?source=blobs` work; database-only routes answer 503/400.
- **`main.py`**: Entry point — launches `app.py` via subprocess using the conda env's Python. The `start-idtrackerai-validator-server` console script calls this.
- **`backend.py`**: Loads experiments (`load_experiment`; `load_experiment_without_database` from `metadata.yaml`, `<date>.conf` and the folder name's start hour, starting at `first_chunk` or the last chunk recorded; imgstore writes `index.db` when the folder has none), reads idtrackerai config from SQLite, runs segmentation via `idtrackerai._process_frame`, and provides frame annotation/drawing utilities.
- **`database.py`**: `DatabaseManager` dynamically creates Flask-SQLAlchemy models at runtime. Table names have a `_VAL` suffix when the experiment has been validated (e.g., `ROI_0_VAL`, `IDENTITY_VAL`). The suffix is auto-detected by `check_if_validated` or set via `USE_VAL`.
- **`experiments.py`**: Experiment names ↔ folders: `to_relpath` (folder relative to `$FLYHOSTEL_VIDEOS`, the form of `SELECTED_EXPERIMENT`), `to_flat` (flyhostel's name), `experiment_folder` (top-level `FlyHostel<N>/<X>X/<date>`), built on `flyhostel.utils.experiment`. Multi-arena recordings keep each arena as its own imgstore + database in `<experiment>/arenas/<n>/` (`…_arena<n>`); use these helpers instead of `replace("/", "_")`. `INDEX_COMMAND` lists the databases of experiment folders and of their arenas (other depth-4 folders pruned).
- **`constants.py`**: Feature flags (`INCLUDE_POSE`, `WITH_FRAGMENTS`) and defaults (`first_chunk=50`, `FRAMES_DIR`).
- **`ethogram.py`**: `register_ethogram(app, ...)` adds `/api/ethogram/*` routes (merged from the behavior-viewer project). `/track` (what the Ethograms tab draws): per-second winner of `prediction2` from the feather (`TRACK_BEHAVIORS`: inactive, inactive+micromovement, feed, groom, walk; `TRACK_MERGED` folds inactive+pe / inactive+rejection into inactive; background → -1) with its mean score (%), `zt0` of movie time 0; read from the figure JSON when the feather is gone; ~0.6 s, cached per file mtime. Also serves pre-rendered plotly ethograms (`/figure`, no longer used by the client) and HLS movies from `<basedir>/motionmapper/<NN>/` (`<fly>.json`, `<fly>.feather`, `movie/movie.m3u8`). The figure x axis is seconds since movie start; frame = `first_chunk*chunksize + t*framerate`, with `first_chunk` read from the feather. A fly with the feather but no JSON gets its figure drawn on first `/figure` request (`_ensure_figure`: `draw_ethogram` on the first 24 h, `t0 = first_chunk*chunksize`, ~15 s; `/api/ethogram/flies` gives `drawn`). Fly ids may carry an arena (`…_arena1__00`). Replaces the behavior-viewer project (its user systemd service, port 5300, is disabled).
- **`deg_labels.py`**: `register_deg_labels(app)` adds `/api/ethogram/<fly>/deg_labels`: deepethogram labels (training data of the behavior RF) made in the Ethograms tab. Project by framerate as flyhostel's `DEGLoader.get_deg_data_dir` (150 → `FlyHostel_deepethogram`, else `_47fps`); a chunk of a fly is `DATA/<experiment>_<chunk:06d>_<local id:03d>/<chunk:06d>_labels.csv` (1 / 0 / -1 not labelled, one row per frame), local id from `get_local_identities_from_experiment` (what `filter_by_id` reads back). Labelling movie seconds [start, end) writes their `framerate` rows per second (split across chunks; `PRESETS` = the RF classes as `apply_semantic_rules` reads them, or any columns; given columns 1, others 0; `null` → -1), atomic per file under a per-chunk lock, ≤ 1 h at once, logged to `$DEG_LABELS_LOG`. A missing folder / labels file is made by `deg_add_video.py` (standalone, run with `$DEG_PYTHON`): copies `<basedir>/flyhostel/single_animal/<lid>/<chunk>.mp4`, deepethogram's record.yaml and stats.yaml (stride 10, ~30 s), an all -1 labels file, and drops today's `DATA/index_<date>.pkl` so the GUI sees it, printing `@@PROGRESS <fraction>` (its stats loop's `tqdm` replaced); a POST that needs such a folder answers 202 with a job (one item per folder, then the write, `result` = the usual response; clearing never makes folders); the project's `project_config.yaml` is left untouched. `/deg_videos` premakes folders of the cursor's chunk and N chunks before / after it. GET returns runs `[start, end, class]` of labelled seconds (`CLASSES`: presets, `other`, `mixed` = frames of the second differ), per file cached by mtime, and `undo`. Undo: each write keeps the rows it replaced and wrote (in memory, `UNDO_DEPTH` writes per fly) under the client's `action` id; `POST …/deg_labels/undo` restores the last action's writes in reverse (all or nothing, 409 if the rows changed since) and moves them to the redo stack; `…/redo` writes them again, a new write empties it; GET also gives `redo`.
- **`overview.py`**: `register_overview(app)` adds `/api/overview`: reads `METADATA` (`ethoscope_metadata`, chunks) of every database in `index.txt` (thread pool, cached per file until its mtime changes) for the Overview tab. Fly columns are discovered, not hard-coded; junk columns (`" "`, `_`, `03-02`) and `NONE`/`nan` values are dropped. `merge_light_cycle` gathers the light cycle (LD/DD/LL), which older sheets wrote in `condition`, `experiment` or at the end of `vial`, into `light_cycle` (in the response only, databases untouched), with `light_cycle_source` per fly and `light_cycle_flags` per experiment (listed under "Non-standard light cycle encoding" in the Overview tab). `scan_not_analyzed` adds the experiments of the metadata sheets (latest `*metadata<N> - <sheet>.csv` in `$FLYHOSTEL_METADATA` of each sheet under `SHEETS` in `$GOOGLEAPI_CONFIG`) whose folder exists but has no `*db` other than `index.db`; rows with an `arena` (basedir `FlyHostel<N>/1X/<date>`, the arena's NX) map to `FlyHostel<N>/*X/<date>/arenas/<arena>` (`_sheet_experiment`), so unanalyzed arenas are listed one by one; `rebuild_index` runs the index command. Each experiment gets `deg_videos` (`deg_labels.labelled_videos`: DEG video folders of `$DEG_PROJECTS/DEG/*/DATA` whose labels file has a cell ≠ -1, per file cached by mtime/size, also in `deg_labelled.json` next to `$DEG_LABELS_LOG`; ~20 s cold).
- **`metadata_sync.py`**: `register_metadata_sync(app)`: refresh an experiment's `ethoscope_metadata` from the Google sheets in two steps (preview job with checks, then apply), and `predownload` for many experiments (`download_metadata_batch.py`, standalone, reuses googleapi's own filtering so the CSVs equal the CLI's; ~30 s for all). Arenas (`…/arenas/<n>`) download with `--arena <n>` (batch: `arena` per experiment) and are checked against the arena's number of animals (its conf) and `arena` column. Runs `$DOWNLOAD_FLYHOSTEL_METADATA` (default: the `rapids-23.04` env's `download_flyhostel_metadata`, which needs a valid token in `~/.config/googleapi/`; 300 s timeout).
- **`jobs.py`**: In-memory registry of background jobs (daemon threads) with per-item progress, polled by the frontend console. A job may carry a JSON `result` for the client. The last 50 finished jobs are kept.
- **`cvat.py`**: `register_cvat(app, ...)` adds `/api/cvat`: CVAT projects named after the loaded experiment (`FlyHostel1_3X_<date>`, optionally with a suffix such as `_long`; exact name first) and every frame of their tasks as `frame_number -> [task, job, task frame]` (image `<experiment>_<chunk>_<frame0>_<block>.png` = frame `frame0 + block`; the exact-name project's, then the newest task wins). Cached 5 min per experiment (~5 s to build). `build_index`, `configured`, `public_base` and `frame_url` are also used outside Flask by flyhostel's `integrate-human-annotations` to print the CVAT links of frames that still have problems.
- **`data_management.py`**: `register_data_management(app, ...)` adds `/api/data_management*`: every `FlyHostel<N>/<X>X/<date>/` folder of `$FLYHOSTEL_VIDEOS` walked (symlinks inside not followed) and compared with its copy in `$FLYHOSTEL_BACKUP`. `is_critical` mirrors what flyhostel's backup (`flyhostel/scripts/main.py` → `FlyHostelGroup.backup`, `FlyHostelLoader.backup`) copies, raw chunks for chunks < `BACKUP_CHUNKS` (400), pose only for those tracked in `ROI_0` (`tracked_chunks`: first/last chunk, separate MIN and MAX queries so both use the index); a critical file is backed up when its copy has the same size and is not older. Status `ok` / `outdated` / `incomplete` / `none`; `problems` lists tracked chunks (`tracking_gaps`) or raw chunks (`raw_gaps`) that are not consecutive, shown as "⚠ gaps"; `local_only_bytes` = everything without an identical copy. Scans run as a job (one thread per FlyHostel, minutes on the HDDs), kept in `$DATA_MANAGEMENT_CACHE`. Delete rescans first and refuses unless `ok`, the experiment is not loaded and its folder does not resolve into the backup; it then removes the folder and its `index.txt` line.
- **`qc.py`**: `register_qc(app, get_state)` adds `/api/qc`: frames of the loaded experiment whose IDENTITY (or IDENTITY_VAL, following `use_val`) rows are not exactly the N flies with distinct non-zero identities (with 1 fly identity 0 is the fly, flyhostel's `get_identities` → `[0]`: one row of any identity is ok), over every STORE_INDEX frame of the tracked chunks (frames without rows count). Bad frames split into `unidentified` (groups: a row with identity 0), `not_detected`, `other`; per chunk: counts, flies identified on its first / last frame (the concatenation links them; a fly missed there can leave later chunks without its identity or rows), CONCATENATION `is_broken`/`is_inferred`, 10 s bins; runs of bad frames (joined across chunks, 200 longest). One grouped query per chunk (~0.1 s), run as a job, kept in memory and in `$QC_CACHE_DIR` (default `~/.cache/idtrackerai-validator/qc/`) while the database mtime and `CACHE_VERSION` are unchanged (bump it when the rules change).
- **`sleap_labels.py`**: `register_sleap_labels(app, get_state)` adds `/api/sleap/*`: SLEAP pose ground truth of the loaded experiment, written into the training files of `$SLEAP_LABELS_DIR` with sleap-io 0.9.5 (pinned: its files load unchanged in SLEAP 1.3.3's sleap-label, checked frame by frame). A video of these files is one chunk of one fly, `SLEAP_DATA/<experiment>_<chunk:06d>_<lid:03d>/<same>.mp4` (older entries `…/<chunk>.mp4` or `<experiment>_<chunk>/<lid>/<chunk>.mp4`, relative to the .slp or absolute; `VIDEO_RE`), a copy of `flyhostel/single_animal/<lid>/<chunk>.mp4`, so frame_idx i = frame chunk × chunksize + i and coordinates are the pose file's; lid ↔ fly by `deg_labels._local_identities`. `LabelsFile`: the file in memory (`open_videos=False`: ~4 s to read and to save instead of ~20 s), one user instance per frame (replaced on write, `from_predicted` = the frame's prediction; points not visible keep their position, as sleap-label), a chunk not in the file adds its video (copied into `SLEAP_DATA`). Saved `SAVE_DELAY` (2 s) after the last change by a timer thread (temporary file + `os.replace`), never over a file changed on disk since read (`/reload` drops the changes), backed up before its first write. Images: `VideoFrames` (cv2 seek, as sleap-label 1.3.3 reads them; the file's `SLEAP_DATA` video first, an old copy can differ from today's single-animal video). New instances start from the file's prediction, else the fly's pose file (only if it exists: `get_h5_file` would compile it), else `place_template`: the mean user instance in the fly's frame of reference (thorax origin, head +x, in head–abdomen lengths) laid on the frame's dark blob (Otsu + moments; head–abdomen = `BODY_FRACTION` 0.64 of the blob length, measured; the head may be at either end).
- **`pose.py`**: `register_pose(app, get_state)` adds `/api/pose/*`. A fly's pose is flyhostel's compiled SLEAP file (`<basedir>/motionmapper/NN/pose_raw/<experiment>__NN/<experiment>__NN.h5`, `recreate_pose_file` when missing; index 0 = first chunk of `files` × chunksize); also holds the cache of open pose files (`get_h5_file`, `close_h5_files`, 64 MB chunk cache) used by `/api/tracking`. `recompile_pose_file` compiles it again into `pose_raw/.recompile-NN/` and swaps it in (the open handle is closed first). A body part is detected when its `point_scores` > 0 (SLEAP's 0.2 threshold; NaN coords otherwise). Pose score = sum of the confidences of the detected parts / number of `SCORED_NODES` (the 12 the viewer draws, leg joints left out) — SLEAP's centered-instance instance score, normalized. Pose QC (QC tab): reads only `point_scores` chunk by chunk (~20 s per fly, minutes from cold HDD) → per chunk and 10 s bin means of parts detected / confidence / score, per body part detection % and confidence, histograms, 50 worst bins; one job item per fly, cached in memory and `$QC_CACHE_DIR/pose/<fly>.json` while the pose file's mtime and `CACHE_VERSION` are unchanged.
- **`dropbox.py`**: is a local file backed up to Dropbox? The Dropbox client does not run here; `list_remote` reads `$DROPBOX_REMOTE/<relpath>` with `rclone lsjson --hash` (sizes and Dropbox content hashes, nothing downloaded, ~7 s per experiment folder), `content_hash` computes the same hash locally (SHA-256 of the SHA-256 of each 4 MiB block), `compare` → `missing` / `different size` / `same size` / `verified` / `different content`, `to_relpath` also accepts paths through the drives the `FlyHostel<N>` links point to. CLI: `python -m idtrackerai_validator_server.dropbox [--verify] FILE...` (exit 1 unless all are on Dropbox). `data_management.dropbox_check` uses it per experiment: top-level files by size, raw chunk files (`RAW_RE`: `.mp4/.npz/.png/.avi`) outside `tracked_chunks` by content when `verify` (`deletable_bytes` = verified); kept in `dropbox.json` next to `$DATA_MANAGEMENT_CACHE`.
- **`dropbox_files.py`**: `register_dropbox_files(app)` adds `/api/dropbox/files*` for the "Files on Dropbox" card: a Dropbox folder listed recursively (`rclone lsjson -R --hash`, ~6 s per 3000 files, last listing per folder in memory) with each file's local copy (`no local copy`, `different size`, `same size`, `verified` / `different content` when its hash is cached, `local copy in backup`); deleting the given paths on Dropbox (one job at a time) lists again, hashes each local copy, lists again and runs `rclone delete --files-from-raw` only for files whose Dropbox hash matched and neither copy changed, then lists to count what went; `safe: false` skips the local checks and deletes every given file whose Dropbox entry did not change between the two listings. Local hashes cached in `dropbox_hashes.json`, deletions logged to `deleted_from_dropbox.jsonl`, both next to `$DATA_MANAGEMENT_CACHE`.
- **`restore.py`**: `register_restore(app)` adds `/api/data_management/restore*`: experiment folders on Dropbox (`rclone lsf -R --dirs-only --max-depth 3`, ~15 s) with nothing at their path in `$FLYHOSTEL_VIDEOS`, annotated with the DEG videos made from them (`deg_annotations`: labelled = holds a `*labels*.csv`, per project) and, once inspected (`rclone lsjson -R`), size / raw chunks / databases; kept in `restore.json` next to `$DATA_MANAGEMENT_CACHE`. Restoring copies with `rclone copy` into `FlyHostel<N>/.restoring/<X>X/<date>/` (5 levels deep: not indexed, not scanned; restoring again resumes it), one experiment at a time per drive, refused if the drive would keep < `RESTORE_MARGIN` (50 GB) free; when every Dropbox file is there with its size it is renamed into place, its databases are appended to `index.txt`, it is scanned, and logged to `restored.jsonl`.
- **`trim_raw.py`**: CLI deleting raw chunk files (`RAW_RE`) before the first or after the last chunk tracked in `ROI_0` that are verified on Dropbox: listed, hashed locally, listed again, deleted only if the Dropbox entry and the local size/mtime are unchanged; each deleted file is logged in `<experiment>/deleted_raw_chunks.jsonl` (restore with `rclone copy <dropbox_path> <folder>`). Skips experiments without database or tracking, multi-arena recordings and folders resolving into the backup. Dry run unless `--delete`: `python -m idtrackerai_validator_server.trim_raw [--delete] [--from-file F] EXPERIMENT...`; one worker per drive.
- **`compress_slp.py`**: CLI compressing `flyhostel/single_animal/*/*.predictions.slp` (also under `arenas/<n>/`) in place with `h5repack -f GZIP=4` (~3.7x smaller, lossless): the copy (`.<name>.repack-tmp.slp`, SLEAP picks its reader by extension) is compared object by object with h5py (attributes, dtype, shape, maxshape, data bytes), the first file of each experiment also loaded with SLEAP from both (`$SLEAP_PYTHON`), then given the original's mtime and swapped in with `os.replace`. Skips compressed files, links and files modified in the last `--min-age` hours (24). Logs to `$COMPRESS_SLP_LOG` (`~/.cache/idtrackerai-validator/compressed_slp.jsonl`). Dry run unless `--apply`: `python -m idtrackerai_validator_server.compress_slp [--apply] [--all | EXPERIMENT...]`.

Criterion = GPU memory (the NVENC failures of imgstore-crop-arenas were `CUDA_ERROR_OUT_OF_MEMORY`, after which it retries the chunk in 3600 s): the head starts when `estimate ≤ total − used − reserved − MARGIN_MB`, `used` from nvidia-smi (`resources.read_gpus`, every process), `reserved` = Σ over running jobs of registered kinds (queued or found by `external()`, e.g. started by hand) of estimate − their process tree's memory now; estimate = `memory_mb` or 1.1 × the peak of the kind's last `LEARN_RUNS` (5) done runs when higher, capped at total − margin; `max_running` per kind (sleap-train 1); strict FIFO (no backfill; `/front` moves one up), one start per tick (`TICK_S` 10 s, woken by enqueue/cancel). ### Database Schema (SQLite)

Tables accessed (with or without `_VAL` suffix based on validation status):
- `ROI_0` — centroid positions per frame (`frame_number`, `x`, `y`, `in_frame_index`, `area`, `fragment`)
- `IDENTITY` — identity assignments (`frame_number`, `in_frame_index`, `identity`, `local_identity`)
- `CONCATENATION` — chunk-level identity linking
- `METADATA` — experiment metadata (`field`/`value` key-value store: `framerate`, `chunksize`, `date_time`, `idtrackerai_conf`, `ethoscope_metadata`)
- `AI` — frames where AI (YOLOv7 or idtrackerai) intervened

## Key Configuration Notes

- **`first_chunk` in `constants.py`** controls which video chunk loads at startup (default: 50).
- `INCLUDE_POSE=False` in `constants.py` — pose support is disabled and not fully implemented (raises `NotImplementedError` if enabled).
- `./frames/` (`FRAMES_DIR`) is still wiped at server start but no longer written: frames are encoded in memory.
- Sleep-bout video helpers live in flyhostel (`flyhostel/data/pose/loaders/sleep_videos.py`, also `FlyHostelLoader.record_all_sleep_bouts()`); `ethogram.py` and `utils.py` import them. The server env imports flyhostel from wherever it is installed, so that copy must contain the module.
